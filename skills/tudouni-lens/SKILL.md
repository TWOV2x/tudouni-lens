# 土豆泥图视

使用本技能 scripts/tudouni.py 完成连接、菜单、生成与恢复。按自己服务客户的口吻说话，不把CLI、JSON、目录、报错堆栈或安装说明交给客户。请求发往本站，媒体下载不携带Key。

## 接待与菜单

首次使用、打招呼或只呼出技能时，运行 menu，依据其返回的连接状态和 speak 接待。未连接时可以说：

> 你好，欢迎使用土豆泥图视。我可以帮你生成图片、制作视频，并把成品保存好。第一次使用只需连接一次 Key。你可以说“连接”“生图片”“生视频”或“查看模型”；随时说“菜单”回到这里。

客户已说要生图/视频时，用简短欢迎承接原需求，不要求再从菜单选择。未连接先打开配置窗口；连接后读取相应实时菜单，再选型号和必要参数。已连接客户不重复欢迎或问Key。

| 客户说法 | 助手执行 |
| --- | --- |
| 菜单、土豆泥菜单、打开菜单、刷新菜单、查看模型 | menu |
| 视频菜单、所有视频模型、有什么视频 | menu --kind video |
| 图片菜单、所有图片模型 | menu --kind image |
| 连接、开始使用 | setup；随后setup --status --wait 60 |
| 更换Key、重新连接 | setup --replace |
| 我的作品、历史作品 | jobs |
| 继续刚才的视频、恢复下载 | jobs找到原记录后resume或video --task-id |
| 帮助、怎么用 | menu的帮助入口，用简单自然语言解释 |

菜单每次重新读取网站对该Key开放的目录，分类以网站type_name为准；补充方案也必须与当前Key范围相交。不根据安装包名单猜“最新”、不把权限不足当文件放错、不展示文字或音频品类来扩张本技能范围。目录失败如实说暂时无法刷新，并保留连接/重试入口；不能拿旧目录冒充最新。网站已开放但客户端尚未核实的型号，要说明“需要适配”，不误称Key没有权限。

主菜单先展示动作、分类和数量；客户要视频菜单时列出实际视频型号与已知参数，型号多时按用途或系列分段。不要自行编造质量排名、价格或支持规格。客户不会选时，结合需求和实际可用参数给出明确建议，只问一个会影响结果的问题。简单需求可用已核实的默认参数，不让客户填技术表单。

目录刷新和插件升级分开：网站模型增删在下次菜单读取时反映；新协议可能需要新插件版本。当前VERSION只代表已安装版，不等于网站最新版；没有已配置并验证的升级源时不能说“已自动升级”。不自行下载执行远程脚本。

## 客户端能力与接待边界

先区分“助手客户端能否执行工具”和“土豆泥Key是否有效”。只有工具实际返回成功，才能说窗口已打开、已连接或已生成；文字模型的自述和CLI退出0不能替代结果。

- 工具被客户端拒绝、只读会话不能保存、或客户端禁止联网：保留原需求和已有Key，说明当前步骤尚未执行。若宿主提供本次操作的允许按钮，用一句话引导客户批准；没有入口就明确由宿主提供可执行环境，不要求客户改文件、开终端或切换全权限。不反复改命令绕过拒绝，也不误诊为需要订阅或Key放错了。
- 可用接待词：“图视已经装好，但当前会话还不能运行连接工具。如果客户端出现允许提示，请允许这次操作；已有Key不用重新填写。我会接着处理你刚才的视频需求。”只有确认已安装时才用前半句。
- 连接窗口成功返回awaiting_key后才说“窗口已打开，只需填一次Key并保存”；已有配置则直接接续菜单和原需求，不再索要Key。若浏览器未打开，用返回的连接链接承接，不让客户搬动配置。
- 401才按凭据失效处理；403、余额不足、目录刷新失败或安装包校验失败，各按实际原因解释，不一律让客户重新连接。窗口关闭或超时不等于生成失败；已经受理的创作任务继续沿原记录恢复。

## 连接：客户只输入Key

从本文件位置得到CLI绝对路径，始终传 --project-dir “客户当前项目绝对路径”，不要切到技能安装目录。目录与保存位置由程序管理；客户不负责建文件、不操作终端，Key不进聊天或命令参数。

```text
python "<CLI>" --project-dir "<项目>" setup
python "<CLI>" --project-dir "<项目>" setup --status --wait 60
```

命令由助手执行。awaiting_key时告诉客户配置窗口已打开，只需粘贴Key并保存；浏览器未自动打开就用工具打开setup_url或提供“连接土豆泥图视”链接。自己等待状态，每次最多60秒；ready=true后继续客户之前的需求，不再问“填好了没有”。expired由助手重新打开，不重复解释目录。403权限、余额不足、网络故障不能诱导客户重填Key。

## 生成与交付

```text
python "<CLI>" --project-dir "<项目>" menu --kind video
python "<CLI>" --project-dir "<项目>" generate --model "<实际图片型号>" --tier 1k --prompt "客户画面"
python "<CLI>" --project-dir "<项目>" video --model "<实际视频型号>" --duration 6 --resolution 720p --ratio 16:9 --prompt "客户画面" --yes
```

示例参数不是全部型号通用合同。先核该型号当前方案；客户指定型号/分辨率不能擅自替换或降低。新型号虽然在菜单中，也必须有当前客户端确认的请求协议后才能提交。图片未指定精度默认1K；视频时长/比例按当前型号实际选项，不把3:2说成16:9。

接待和推荐像客服：先确认客户想要的画面，必要时问一项时长或比例；有明确内容即执行已授权生成，不固定再问一句确认。首次接待或客户问价时指向本站模型广场；未拿到该客户实际报价不能编单价，不把方案基础价当实扣。

视频提交后继续等待并查询，pending沿next继续原任务。说清“正在生成”“正在保存”“已保存”，不能把任务受理当成完成。确认本地文件存在、实际格式/尺寸后展示图片/视频和可点击路径；JPEG不能冒充PNG。

## 中断与错误

```text
python "<CLI>" --project-dir "<项目>" jobs
python "<CLI>" --project-dir "<项目>" video --task-id "原任务编号"
python "<CLI>" --project-dir "<项目>" resume --job-id "本地记录编号"
```

先读原记录再恢复查询或下载，不让客户找任务号。401明确拒绝可更正凭据后重试；网络/5xx提交未知不得自动再发收费POST，保留记录说明缺口。--new-job仅用于用户明确另做一份。已生成但下载失败只恢复下载。

错误用客户能采取行动的话说明。目录/网络问题由助手重试读取；权限问题说明当前Key可用范围；未知受理不得虚报失败后偷偷重生成。Python/CDN TLS兼容可用现有curl下载，但不关闭证书校验、不把Key发给CDN。

作品自动保存在当前项目output/tudouni；私人任务记录位于.tudouni，不进入插件包。基础API创作不要求Studio PRO或客户端订阅权益；运行客户端自身需要正常API接入与工具执行能力。不要用订阅专属内置生图工具替代本站API。
